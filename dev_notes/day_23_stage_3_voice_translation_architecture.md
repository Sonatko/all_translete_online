## 1. Смена парадигмы: Отказ от дубляжа в пользу микрофона
На 23-й день разработки была окончательно скорректирована цель **Stage 3**:
* **Что НЕ нужно:** Входящий голосовой дубляж звуков Windows (игры/видео). Эта задача для слуха уже закрыта субтитрами Этапа 1 и озвучкой фрагментов в Этапе 2.
* **Что ЯВЛЯЕТСЯ целью:** **Исходящий голосовой переводчик речи в реальном времени (Real-Time Outgoing S2ST)**.

  - Система с субсекундной задержкой (<400–450 мс) переводит русскую речь в чистый, естественный английский язык.
  - Синтезированная английская речь без виртуальных кабелей отдается прямо в аппаратный канал **Topping E2x2 OTG Loopback**, который выбран как микрофон в Discord, Teams или мультиплеерных играх.

## 2. Разбор парадокса OpenAI Whisper: Почему перевод работает только в английский?
Пользователь задал фундаментальный вопрос: *«Почему Whisper умеет переводить на английский с любого языка, но не умеет переводить на русский язык?»*

### Анатомия датасета и функции потерь OpenAI:
1. Whisper обучался на 680 000 часах аудио.
2. Из них 117 000 часов составляли пары: `[Звук на иностранном языке X] + [Текст субтитров на АНГЛИЙСКОМ языке]`.
3. В архитектуру декодера был жестко зашит токен задачи `<|translate|>`, который безусловно активирует генерацию **только английских токенов**.
4. В датасете OpenAI не было пар `[Английский звук] + [Русский текст]`. Соответственно, обучить декодер выдавать русский перевод с английского звука было невозможно.
5. **Итог:**
   - Для **Этапа 1** (Английский звук -> Русские субтитры) отдельная модель перевода (**Tencent HY-MT 1.8B**) была математически и архитектурно неизбежна.
   - Для **Этапа 3** (Русский звук -> Английская речь) встроенный режим `task="translate"` в Whisper работает «из коробки», поскольку целевым языком является именно английский!

## 3. Модели Faster-Whisper для перевода RU -> EN:
Все мультиязычные чекпоинты Whisper поддерживают перевод RU -> EN:
* `tiny` (~75 МБ): ~15–20 мс на RTX 5070. Ошибается на падежах и окончаниях.
* `base` (~140 МБ): ~25–30 мс на RTX 5070. Сносно на простых словах, плохо на шуме.
* `small` (~460 МБ): ~40–55 мс на RTX 5070. Оптимальный баланс точности и скорости.
* `medium` (~1.5 ГБ): ~100–120 мс на RTX 5070. Высокая точность, но задержка растет.
* `large-v3-turbo` (~1.6 ГБ): ~80–95 мс на RTX 5070. Свежая архитектура с низкой задержкой и отличным пониманием разговорной речи.

## 4. Сравнение движков нейросинтеза (TTS) для английской речи
Синтезатор речи — ключевое звено Stage 3. Проведен анализ существующих решений:
1. **Piper TTS (VITS, C++/ONNX):**
   * Плюсы: 0 МБ VRAM (чистый CPU), задержка ~15–25 мс.
   * Минусы: голос звучит сухо, механически (роботизированный навигатор).
2. **Kokoro-82M (ONNX, Apache 2.0, 2025):**
   * Плюсы: объективная оценка качества UTMOS 4.45 (уровень ElevenLabs), время первого звука (TTFA) ~40–50 мс на GPU, модель весит всего ~150 МБ.
   * Минусы: требует генерации через чистый фонетический пайплайн.
3. **ChatTTS / CosyVoice / F5-TTS:**
   * Плюсы: сверхреалистичные вздохи и эмоции.
   * Минусы: диффузионные архитектуры требуют 4–6 ГБ VRAM и дают задержку 800–1500 мс (непригодно для шутеров и динамичных игр).
4. **Edge-TTS (Облачный Microsoft):**
   * Плюсы: красивый голос.
   * Минусы: сетевой пинг 400–800 мс, зависимость от внешних серверов.

## 5. Выбор архитектурной платформы: `LiveLingo`
Вместо написания сервиса с нуля и вместо опасных попыток встроить второй аудио-поток в `LiveTranslate`, обнаружен референсный опенсорсный репозиторий [roirude/LiveLingo](https://github.com/roirude/LiveLingo).
Он изначально спроектирован под Windows для трансляции микрофона в Discord/Teams с независимыми очередями `capture -> transcribe -> translate -> synthesize -> playback`.

Все наработки и спецификация зафиксированы в `stage_3_voice/README.md`.
Рабочая ветка: `research/stage3-tts-architecture`.
