## 1. Архитектурная задача и решение проблемы вывода звука

### Проблема «смены устройств» в Windows:
В играх (Counter-Strike 2, шутеры на Unreal Engine / Source 2) смена устройства записи Windows по умолчанию (*Default Recording Device*) во время игрового процесса приводит либо к зависанию звукового движка игры на 1–2 секунды, либо к полному вылету аудиопотока (*DirectSound/WASAPI buffer underflow*). 

### Архитектурное решение — Сценарий В: «Раздельные кнопки» (Push-to-Translate с Pass-Through):
Игра **всегда** слушает одно и то же постоянное устройство ввода (`Topping Loopback` или виртуальный кабель `CABLE Output`).
Маршрутизация звука осуществляется полностью программно внутри аудиопотока:

```
[Микрофон пользователя (Behringer XM8500 / PC Mic)]
             │
             ├── [Режим покоя (PTT кнопка ОТПУЩЕНА)] ────────────► [Pass-Through: 0 мс задержки] ──┐
             │   (Прямой сквозной поток исходной русской речи)                                      │
             │                                                                                       ▼
             └── [Режим перевода (PTT кнопка НАЖАТА / F8)]                                  [Topping Loopback /
                 ├─ Pass-Through МГНОВЕННО ГЛУШИТСЯ (Mute) ───► (Русская речь в игру не идет)      CABLE Output]
                 └─ Поток звука ─► [Sber GigaAM CTC] (~70 мс)                                       │
                                         │                                                           ▼
                                  [Opus-MT INT8] (~17 мс)                                     [Игра: CS2 / Discord]
                                         │                                                  (Тиммейты слышат звук)
                                  [Piper / Kokoro TTS] (~25 мс)
                                         │
                                         └─► Английский голос синтезатора ───────────────────────────┘
```

## 2. Реализация в кодовой базе

### 1. Двусторонний Pass-Through в `dizcord/engine.py`:
В класс `Pipeline` добавлена поддержка сквозной передачи звука для исходящего канала (`outgoing`):
* `_check_passthrough()`: разрешает трансляцию микрофона в выходное устройство.
* `_on_audio(chunk)`:
  * Проверяет состояние перевода: `is_translating = (self.segmenter.mode in ("ptt", "toggle") and self.segmenter.ptt_down)`.
  * Проверяет активность воспроизведения синтезатора: `is_ai_speaking = self.engine.outputs.any_playing("outgoing")`.
  * Если перевод не активен и ИИ не говорит — отправляет сырой PCM-чанк напрямую в выходной буфер через `push_live(chunk)`.
  * В момент нажатия PTT или при озвучке перевода — сквозной поток мгновенно глушится, предотвращая утечку русской речи.

### 2. Пакетная оптимизация голосов Piper TTS:
* Обнаружено, что в `dizcord/models/piper/` голоса хранились во вложенных поддиректориях.
* Файлы голоса `en_US-lessac-medium.onnx` и метаданных скопированы в корень каталога голосов.
* Проверено прямое декодирование чанков через `PiperVoice.synthesize` — задержка составила **22–32 мс**, аудиопоток возвращает нормализованный `float32` массив (22050 Гц).

### 3. Автоматический тест графического интерфейса (`test_gui_headless.py`):
Инструментально подтверждено, что:
* `MainWindow` инициализируется за **0.66 мс** без падений и ошибок.
* Профиль `Speed_Gaming` загружает:
  * STT Provider: `gigaam` (Sber GigaAM v3 CTC).
  * Translation Provider: `opus_mt` (MarianMT CTranslate2).
  * TTS Provider: `piper` (Piper TTS VITS).
  * Outgoing Passthrough: `True`.
  * Mic Mode: `ptt` (`f8`).

### 4. Сквозной тест оркестратора (`test_dizcord_speed_pipeline.py`):
* Время обработки 3.23 сек реального голоса («нейронные сети это хорошо»):
  * Распознавание (STT): 140.85 мс
  * Перевод (MT): 17.15 мс
  * Полная оркестровка (Warmed-up E2E): **164.57 мс**!

## 4. Памятка для вечернего подключения аппаратной карты Topping E2x2

Когда вечером будет подключен аудиоинтерфейс **Topping E2x2** и микрофон **Behringer XM8500**:

1. **Физическое подключение:**
   * Микрофон Behringer XM8500 подключается кабелем XLR во вход **Input 1** на передней панели Topping.
   * На канале Input 1 регулятором Gain выставляется уровень (индикатор не должен уходить в красный клиппинг).
   * Если микрофон динамический (XM8500) — фантомное питание `+48V` **выключено**.
2. **Панель управления Topping Control Panel:**
   * В Windows в трее появится панель управления Topping.
   * В разделе маршрутизации (*Routing / Loopback*) канал Loopback назначается на виртуальный источник Topping.
3. **Выбор устройств в Dizcord (вкладка Settings -> Audio):**
   * **Microphone (Вход микрофона):** Выбрать `Topping E2x2 Input 1/2` (ваш голос с Behringer).
   * **Output Device (Выход перевода):** Выбрать `Topping E2x2 Loopback` (или виртуальный кабель, если требуется разделение каналов).
4. **Настройка игры (CS2 / Discord):**
   * В CS2 в настройках микрофона выбирается `Topping E2x2 Loopback` (или `CABLE Output`).
   * **Результат:** 
     * Без зажатия клавиши `F8` игра слышит ваш чистый голос через аппаратный Topping без задержки.
     * При удержании `F8` игра слышит мгновенный английский перевод нейросети.
