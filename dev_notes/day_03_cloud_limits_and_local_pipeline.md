# Дневник разработки — День 3: Анализ облачных лимитов и переход на локальный инференс с подсказками

## 1. Фактический аудит облачных провайдеров (Октябрь 2026)

В ходе тестирования потокового аудиоперевода в реальном времени были получены фактические инструментальные данные по всем заявленным «бесплатным» тарифам:

| Провайдер | Заявлено в статьях | Реальность на бесплатном тарифе (без карты) | Пригодность для субтитров |
| :--- | :--- | :--- | :--- |
| **Groq** | 14 400 запросов/день | **1 000 запросов/день**, 200K токенов/день на всех текстовых LLM. 14.4K оставлено только на фильтр безопасности `prompt-guard`. | Хватает на 15–20 минут видео |
| **SambaNova** | 48 000 запросов/день | **20 запросов/день** (Twenty requests per day). 48k доступно только на Developer Tier с привязкой карты. Моментальная ошибка 429 («high demand»). | Непригодно (умирает за 30 секунд) |
| **Cerebras** | 1M токенов/день | Доступ к API заблокирован баннером «Add payment method» даже для пробных $5. | Непригодно без иностранной карты |
| **Google Gemini (AI Studio)** | До 1 500 запросов/день | `gemini-3.5-flash-lite`: 500 запросов/день, 15 RPM. Старшие Flash (3.5/3.6/3.7) ограничены 20 запросами/день. | Хватает максимум на 15–25 минут |

### Математический вывод:
При частоте распознавания 1 фраза в 2–3 секунды поток генерирует ~1 200–1 800 запросов в час. 
Любой бесплатный облачный API исчерпывает суточный лимит за 15–30 минут работы. Облачные бесплатные тарифы рассчитаны исключительно на чат-ботов (1 сообщение в несколько минут), а не на потоковый стриминг.

## 2. Новая архитектурная цель: Локальный инференс на GPU (CUDA)

### Требования пользователя:
1. **Автономность и бесконечные лимиты**: 0 рублей, 0 облачных API, работа 24/7 без интернета.
2. **Минимальная латентность**: Субтитры должны появляться мгновенно синхронно с речью.
3. **Образовательные подсказки (Language Learning Hints)**: Вывод перевода на строке 1 и выделение сложной лексики / идиом на строке 2 (`💡 <phrase> — <перевод>`).

---

## 3. Исследуемые локальные архитектуры и вопрос видеопамяти (VRAM)

### Главный инженерный вопрос: Действительно ли нужно тратить 4–5 ГБ VRAM?
Нет! Субтитры — это короткие фрагменты текста (от 3 до 15 слов). Нам не нужно удерживать в памяти гигантский контекст чата на 128 000 токенов (на который по умолчанию выделяется львиная доля VRAM под KV-кэш).

Сравнение весовых категорий моделей:
1. **Ультра-компактные SLM (1.5B – 3B параметров, например Qwen 2.5 1.5B / 3B, Llama 3.2 3B)**:
   - Вес в памяти: всего **1.1 – 2.0 ГБ VRAM**.
   - Потребление под задачу субтитров (контекст 512 токенов): минимальное.
   - Скорость: свыше **150–200 токенов в секунду** на RTX 5070.
   - Вопрос: хватает ли у 1.5B–3B моделей интеллекта для качественного выделения идиом и фразовых глаголов?
2. **Средние модели (7B – 8B параметров, например Qwen 2.5 7B, Llama 3.1 8B)**:
   - Вес в памяти: **4.5 – 5.5 ГБ VRAM**.
   - Высокое качество перевода и глубокое понимание контекста.
   - Минус: занимает почти половину памяти видеокарты, что может мешать параллельно запущенным тяжелым играм на Unreal Engine 5.

## 4. Окончательное решение: Истинный KISS (Portable llama-server + Qwen 2.5 3B)

После глубокого анализа вариантов был отклонён ложный KISS (MarianMT + словарный парсер), так как:
1. MarianMT переводит разговорные фразовые глаголы дословно («kick the bucket» -> «пнуть ведро»).
2. Для поиска идиом с разделяемыми местоимениями («figure it out») потребовалось бы писать сложный синтаксический анализатор (нарушение принципа No In-House Coding).
3. Ollama была отклонена из-за скрытых системных служб, оверхеда памяти и задержек при повторной загрузке модели (`keep_alive`).

### Утверждённая архитектура «True KISS»:
- **Автономный бинарник**: Официальный скомпилированный C++/CUDA сервер `llama-server.exe` (лежит локально в `bin/llama_server/`, без установки в Windows).
- **Компактная модель**: `Qwen2.5-3B-Instruct-Q4_K_M.gguf` (1.9 ГБ).
- **Параметры запуска**:
  - `-c 512` — жесткое ограничение контекста (KV-кэш весит всего 40 МБ вместо 4 ГБ).
  - `-ngl 99` — полная выгрузка слоев на RTX 5070 (занимает ровно 2.1 ГБ VRAM из 12 ГБ).
  - `--port 8080` — локальный OpenAI-совместимый эндпоинт `http://127.0.0.1:8080/v1`.
- **Интеграция с LiveTranslate**:
  - Ни строчки лишнего кода в LiveTranslate не меняется.
  - В настройках моделей подключается локальный адрес `http://127.0.0.1:8080/v1`.
  - Скорость перевода: **~160–180 токенов/сек** (~0.12 секунды на субтитр).
  - Подсказки `💡` формируются точно и выводятся на отдельной строке.

## 4. Архитектурная реализация: Автономный локальный стек (True-KISS)

### 4.1. Выбор вычислителя (CPU vs GPU)
* **Анализ узкого места (VRAM Bottleneck):**
  * Видеокарта NVIDIA GeForce RTX 5070 имеет 12 ГБ VRAM.
  * Современные игры в разрешении 1440p с Ray Tracing / Frame Gen потребляют 10.5–11.8 ГБ VRAM.
  * Запуск локальной LLM в видеопамяти приводил бы к превышению лимита 12 ГБ и сбросу текстур игры в оперативную память (*VRAM Thrashing*), вызывая тяжелые статтеры.
* **Решение:**
  * Инференс LLM вынесен на процессор **AMD Ryzen 7 7800X3D (8C/16T, Zen 4 с AVX-512)** и 32 ГБ DDR5.
  * Видеокарта сохраняет 100% своей памяти для игр (0 МБ VRAM расхода на LLM).
  * Нагрузка на процессор кратковременная (всплеск ~0.25с на реплику).

### 4.2. Спекулятивное декодирование (Speculative Decoding)
* **Основная модель (Target Model):** `Qwen2.5-3B-Instruct-Q4_K_M.gguf` (2.1 ГБ).
* **Модель-черновик (Draft Model):** `Qwen2.5-0.5B-Instruct-Q4_K_M.gguf` (491 МБ).
* **Принцип:** Микро-модель набрасывает черновик на 3 токена вперед (`--spec-draft-n-max 3`), основная модель верифицирует их за один параллельный проход.
* **Прирост производительности:** Ускорение генерации на CPU в 1.6x–2.0x раза без потери качества перевода.

### 4.3. Обучающие подсказки и GBNF-грамматика
* Создана грамматика `bin/llama_server/grammars/subtitle_hints.gbnf`, математически ограничивающая генерацию форматом:
  * Строка 1: русский перевод.
  * Строка 2 (опционально): `💡 <выражение> — <перевод>`.
* Исключены любые галлюцинации, вступительные слова и разметка.

### 4.4. Интеграция с LiveTranslate
* В `bin/LiveTranslate/user_settings.json` настроен коннектор к локальному API:
  * URL: `http://127.0.0.1:8080/v1`
  * Модель: `qwen2.5-3b-instruct-q4_k_m`
* Приложение LiveTranslate запускается без лишней консоли CMD через `pythonw.exe`.
