## 1. Проблема масштабируемости: «Не у всех же такой процессор»

Разработка на топовом процессоре (AMD Ryzen 7 7800X3D, 8 ядер / 16 потоков) создает обманчивое впечатление: кажется, что можно поставить жестко 4 или 8 потоков. Однако на ноутбуках или более скромных ПК (например, 4 ядра / 8 потоков или 6 ядер) это вызовет:
- 100% загрузку ядер,
- нагрев и троттлинг,
- микро-фризы в играх, откуда захватывается звук.

### Инженерное решение: Адаптивная топология CPU (CPU Auto-Topology)
Вместо жестко закодированного числа потоков движок ASR должен динамически опрашивать аппаратную архитектуру машины:
```python
import os
import psutil

def get_optimal_asr_threads() -> int:
    physical_cores = psutil.cpu_count(logical=False) or os.cpu_count() or 4
    # На 4-ядерниках берем 2 потока (оставляя 2 ядра играм и плееру)
    # На 6-8+ ядерниках берем 3-4 потока (максимум для линейного масштабирования ONNX)
    if physical_cores <= 4:
        return 2
    elif physical_cores == 6:
        return 3
    else:
        return 4
```
Это гарантирует, что программа «летает» на мощных ПК и бережно работает на слабых ноутбуках, не мешая играм.

## 2. Разрыв восприятия: Сырая скорость модели vs Задержка конвейера

Наши инструментальные замеры показали:
- **Alibaba SenseVoice-Small:** 206 мс на 7 сек аудио (~35 мс на короткую фразу).
- **NVIDIA Parakeet-TDT:** 420 мс на 7 сек аудио (~75 мс на короткую фразу).

Но пользователь вживую ощущал задержку. Почему?
1. **Режим накопления VAD:** При выключенном `Incremental ASR` программа ждёт, пока спикер сделает паузу. Если реплика длится 4 секунды — вывод задерживается на все 4 секунды.
2. **Переход на чистый C++ VAD:** Перевод VAD на нативную библиотеку Sherpa-ONNX (`VoiceActivityDetector`) с шагом 100 мс и автоматическим нарезанием смысловых фраз по минимальным дыхательным паузам (200–250 мс).

## 3. Специфика двуязычных субтитров (Dual-Language Subtitles UX)

Стандарты Netflix и BBC (17–20 CPS, макс 42 символа) разработаны для **одноязычных субтитров** (фильм на языке оригинала или дублированный).

В нашей системе субтитры **двуязычные**:
* **Строка 1 (Оригинал, белый цвет):** Служит для контекста и изучения языка (слух сопоставляет звуки с буквами).
* **Строка 2 (Перевод, желтый/золотистый цвет):** Является семантической доминантой (глаз сразу считывает смысл).

### Правила профессионального профиля для двух строк:
1. **Правило доминанты:** Строка перевода должна быть чуть крупнее (например, 26–28pt) и контрастнее, чем строка оригинала (22–24pt).
2. **Лимит строк:** Строго 1 строка на оригинал + 1 строка на перевод (суммарно не более 2 строк текста на экране). Если фраза длинная — она должна сменяться инкрементально, а не громоздиться в 4 этажа.
3. **Минимальное удержание (Anti-Flicker):** Минимальное время показа карточки — **1.5 секунды**, даже если сказано всего два слова («Yes, sir»). Это предотвращает стробоскопическое мигание текста перед глазами.
