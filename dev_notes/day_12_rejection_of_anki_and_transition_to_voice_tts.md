# День 12: Отказ от интеграции Anki и переход к Этапу 3 (Синтез речи / Голос)

## 1. Контекст решения и отказ от Anki (Retrospective)

В рамках Этапа 3 изначально исследовалась возможность автоматического создания карточек интервального повторения в Anki по горячей клавише при выделении незнакомых слов на экране.

### Причины отказа от подхода Anki:
1. **Высокое когнитивное трение (Cognitive Friction):**
   * Вместо непрерывного погружения в контент (игры, видео, аудио) сбор карточек превращается в рутинную ручную работу. Карточки накапливаются, требуют отдельного времени на повторение в приложении Anki и отвлекают от живого потока перевода.
2. **Конфликты системных хоткеев в Windows:**
   * Одиночные функциональные клавиши (`F10`) в Windows глобально резервируются видеодрайверами (GeForce Experience), оверлеями (Xbox Game Bar, Discord) или вызывают меню активного окна (`WM_SYSKEYDOWN`), сбрасывая фокус и выделение текста.
3. **Принцип максимальной пользы для пользователя:**
   * Пользователю не нужны сложные базы карточек и отдельное приложение для зубрежки. Гораздо выше практическая ценность **голосового сопровождения (Voice / TTS)**: когда перевод звучит прямо в наушниках в реальном времени, освобождая глаза.

## 2. Новый фокус Этапа 3: Голосовой перевод (Voice / Text-to-Speech)

### Целевая задача:
Обеспечить мгновенное, естественное голосовое озвучивание переведённого текста (английский -> русский) параллельно с визуальными субтитрами.

### Ключевые требования к голосовому движку (TTS):
1. **Минимальная задержка (Ultra-Low Latency):**
   * Задержка генерации аудио должна быть минимальной (< 100-200 мс), чтобы озвучка не отставала от субтитров и оригинального звука.
2. **Нулевой или минимальный расход VRAM:**
   * Видеокарта уже нагружена локальной языковой моделью NLLB 1.3B (FP16) и распознаванием речи Whisper. Движок TTS должен либо эффективно работать на CPU (например, через ONNX Runtime), либо использовать ультралегкие архитектуры.
3. **Естественное звучание:**
   * Отсутствие "роботизированного" металлического тембра, чёткая русская дикция с правильными ударениями.
4. **Автономность и стабильность:**
   * Готовое решение в виде standalone-модуля или интеграции в текущий пайплайн, работающее без сбоев в Windows.

## 3. Анализ кандидатов на роль голосового движка

| Движок TTS | Архитектура | Требования к ресурсам | Скорость (RTF) | Качество русской речи |
| :--- | :--- | :--- | :--- | :--- |
| **Piper TTS** | VITS / ONNX | CPU (1-2 потока, ~50 МБ ОЗУ) | **Ультрабыстро** (< 50 мс) | Отличное, чистое оффлайн-звучание |
| **Edge-TTS** | Microsoft Neural Cloud | 0% CPU, 0% VRAM (Cloud API) | Очень быстро (~100-150 мс) | Эталонное студийное качество |
| **Silero TTS** | PyTorch / ONNX | CPU / лёгкий GPU | Быстро (~80-120 мс) | Классический стандарт для русского языка |
| **Kokoro-82M** | StyleTTS2 / ONNX | CPU / лёгкий GPU (~80M параметров) | Быстро (~100 мс) | Высокое качество, активно развивается |

## 4. Следующие шаги
1. Согласовать с пользователем формат озвучки (полностью локальный оффлайн-движок Piper TTS или студийный оффлайн/онлайн вариант).
2. Настроить вывод синтезированного звука в системный аудиопоток или отдельное аудиоустройство.
3. Связать поток перевода из пайплайна с голосовым воспроизведением.
